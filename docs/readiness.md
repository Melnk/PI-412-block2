# Проверка основы разработки

Проверено 22.11.2026. Это подготовка окружения, а не результаты законченного проекта.

| Модель | Выполнены запросы | Верные ответы в 3 smoke-сценариях | Медиана latency |
|---|---:|---:|---:|
| qwen | 3/3 | 2/3 | 884 ms |
| liquid | 3/3 | 3/3 | 2338 ms |
| smol | 3/3 | 3/3 | 3267 ms |

На задаче без достаточных доказательств Qwen выдумала причину про authentication token. Исходный ответ сохранён.
LFM и Smol в этом примере вернули unknown. Три задачи недостаточны для оценки общей надёжности или строгого сравнения моделей.

Локально прошли 20 pytest-проверок, Ruff и pip check. Это тесты инфраструктуры; часть HTTP-адаптера проверяется с MockTransport.
Отдельно выполнены 9 настоящих LLM-запросов и HTTP-запросы к запущенному Uvicorn API, где все 3 model endpoints были готовы.
PyTorch CPU выполнил forward/backward; SQLite поддерживает FTS5. GGUF проверены по SHA-256.

VM: отдельный Ubuntu 24.04 x86_64 guest, без mounts хоста, пользователь incidentlab без sudo. Сеть разработки пока не закрыта.
Полного agent workflow, обученного Jev-like scorer, HSTU и заполненных дашбордов пока нет.

Команды повторения: make check; make models-start; .venv/bin/python scripts/doctor.py --ml; make smoke; make models-stop.
make smoke возвращает 1 при обнаруженной ошибке поведения; это ожидаемое свидетельство ограничения выбранной малой модели.
